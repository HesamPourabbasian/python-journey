# Multiprocessing, Pools & IPC in Python

## Introduction

When software tasks require heavy mathematical computation, cryptographic hashing, machine learning model inference, or image and video processing, multi-threading in standard Python cannot scale across multiple CPU cores due to the Global Interpreter Lock (GIL).

To achieve **True Multi-Core Parallelism**, Python provides the standard library **`multiprocessing`** module.

By spawning separate operating system processes—each running its own CPython interpreter with its own isolated memory and independent GIL—`multiprocessing` allows your software to utilize 100% of all available hardware CPU cores.

However, because processes do not share virtual memory, orchestrating worker pools, distributing tasks, and exchanging data requires specialized tools:
- **`multiprocessing.Pool`**: High-level worker pool manager distributing data batches across CPU cores.
- **Inter-Process Communication (IPC)**: Exchanging serialized objects via **`Queue`** and **`Pipe`**.
- **Zero-Copy Shared Memory (`multiprocessing.shared_memory`)**: Sharing gigabytes of memory buffers directly between processes with **zero serialization overhead**.

This lesson explores `multiprocessing.Pool` mapping strategies, IPC primitives, handling process lifecycles, and high-performance zero-copy shared memory.

## Core Concept: The Multiprocessing Architecture & IPC Channels

```
                        MULTIPROCESSING POOL & IPC ARCHITECTURE

    Parent Process (Main Program)              multiprocessing.Pool (4 Workers)
   ┌─────────────────────────────┐           ┌──────────────────────────────────┐
   │ • Pool.map(func, dataset)   │ ════════► │ Worker Process 1 (Core 1) [GIL 1]│
   │ • Inter-Process Comm (IPC)  │           │ Worker Process 2 (Core 2) [GIL 2]│
   │   ├── Queue (Multi-Producer)│ ◄════════ │ Worker Process 3 (Core 3) [GIL 3]│
   │   └── Pipe (Point-to-Point) │           │ Worker Process 4 (Core 4) [GIL 4]│
   └──────────────┬──────────────┘           └──────────────────────────────────┘
                  │
                  ▼ Zero-Copy Shared Memory (Python 3.8+)
   ┌────────────────────────────────────────────────────────────────────────────┐
   │ multiprocessing.shared_memory.SharedMemory (Direct RAM Buffer - Zero Copy!)│
   └────────────────────────────────────────────────────────────────────────────┘
```

## Syntax & Essential Multiprocessing Patterns

```python
import multiprocessing
import time
import os

# 1. Parallel Mapping with multiprocessing.Pool
def compute_square(x: int) -> int:
    return x * x

if __name__ == "__main__":
    # In multiprocessing, ALWAYS protect execution with if __name__ == '__main__'!
    with multiprocessing.Pool(processes=4) as pool:
        numbers = [1, 2, 3, 4, 5, 6, 7, 8]
        results = pool.map(compute_square, numbers)
        print("Pool.map Results:", results)

    # 2. Inter-Process Communication with multiprocessing.Queue
    def worker_producer(q: multiprocessing.Queue):
        q.put(f"Report generated by PID {os.getpid()}")

    ipc_queue = multiprocessing.Queue()
    proc = multiprocessing.Process(target=worker_producer, args=(ipc_queue,))
    proc.start()
    message = ipc_queue.get()
    proc.join()
    print("Received from Child Process:", message)
```

## Detailed Explanation

### 1. `Pool.map` vs `Pool.apply_async` vs `Pool.imap`

The `multiprocessing.Pool` class provides 4 distinct execution methods:

| Method | Execution Mode | Blocking? | Order Preserved? | Best Used For |
|---|---|---|---|---|
| **`pool.map(func, iter)`** | Batch Chunks | **Yes (Blocks)** | **Yes** | Standard batch parallel processing |
| **`pool.apply_async(func, args)`**| Single Task | ❌ No (Async) | No | Fire-and-forget tasks with callbacks |
| **`pool.starmap(func, iter)`** | Unpacks Tuples | **Yes (Blocks)** | **Yes** | Functions taking multiple arguments |
| **`pool.imap(func, iter)`** | Lazy Streaming | ❌ No (Iterator)| **Yes** | Massive datasets in constant RAM |

#### Worker Recycling with `maxtasksperchild`:
In long-running production systems, worker processes that use C-libraries can accumulate memory leaks over time. Set `Pool(maxtasksperchild=100)` to automatically terminate and replace worker processes after they complete 100 tasks, keeping memory clean.

---

### 2. IPC: `Queue` vs `Pipe`

- **`multiprocessing.Queue`**: A thread-safe, process-safe FIFO queue supporting **multiple producer processes and multiple consumer processes**. Built upon an OS pipe with an internal background feeder thread that serializes objects.
- **`multiprocessing.Pipe(duplex=True)`**: A high-speed, lightweight point-to-point connection between **exactly two processes**. Approximately **2x to 3x faster than a Queue** because it avoids queue manager thread overhead.

---

### 3. Zero-Copy Shared Memory (`multiprocessing.shared_memory`)

When standard multiprocessing transmits a 1 GB array across a `Queue` or `Pool`, Python must:
1. Pickle the 1 GB array into bytes (consumes 1 GB RAM).
2. Copy the bytes through the OS pipe (consumes CPU & bandwidth).
3. Unpickle into the child process (consumes another 1 GB RAM).
- **Total: 2+ GB RAM and several seconds of serialization latency!**

**The Solution: Shared Memory (Python 3.8+ PEP 574)**:
`multiprocessing.shared_memory.SharedMemory` allocates a raw memory segment directly in operating system RAM. Both the parent and child processes map their virtual memory pointers directly to the **exact same physical RAM segment**:
- **Zero Pickling**.
- **Zero Network Copying**.
- **Instantaneous Multi-Gigabyte Data Sharing**.

## Examples

### 1. Simple: Parallel Prime Number Verification with `Pool.map`
Distributing compute-heavy prime number calculations across all available CPU cores.

```python
import multiprocessing
import time
import math

def is_prime(n: int) -> bool:
    if n < 2: return False
    if n in (2, 3): return True
    if n % 2 == 0 or n % 3 == 0: return False
    for i in range(5, int(math.isqrt(n)) + 1, 6):
        if n % i == 0 or n % (i + 2) == 0:
            return False
    return True

if __name__ == "__main__":
    test_numbers = [100_000_007 + i for i in range(500_000)]

    print(f"Testing {len(test_numbers):,d} large numbers for primality...")

    t0 = time.perf_counter()
    with multiprocessing.Pool() as pool:
        results = pool.map(is_prime, test_numbers, chunksize=10_000)
    elapsed = time.perf_counter() - t0

    prime_count = sum(1 for r in results if r)
    print(f"✅ Found {prime_count:,d} primes across {multiprocessing.cpu_count()} CPU cores in {elapsed:.3f}s!")
```

### 2. Beginner: Asynchronous Task Dispatching with `apply_async` & Callbacks
Dispatching tasks asynchronously and receiving non-blocking results via callback handlers.

```python
import multiprocessing
import time
import os

def heavy_compute_task(task_id: int, duration_sec: float) -> dict:
    time.sleep(duration_sec)  # Simulate computation
    return {"task_id": task_id, "status": "COMPLETED", "pid": os.getpid()}

def success_callback(result: dict):
    print(f"🎉 [CALLBACK TRIGGERED] Task #{result['task_id']} finished on PID: {result['pid']}")

def error_callback(error: Exception):
    print(f"🚨 [ERROR CALLBACK] Task failed: {error}")

if __name__ == "__main__":
    with multiprocessing.Pool(processes=2) as pool:
        print("Dispatching asynchronous tasks to worker pool...")
        
        # apply_async does NOT block the main program!
        for i in range(1, 5):
            pool.apply_async(
                heavy_compute_task,
                args=(i, 0.2),
                callback=success_callback,
                error_callback=error_callback
            )

        print("Main thread continues executing other logic without blocking...")
        pool.close()
        pool.join()  # Wait for pool workers to finish
```

### 3. Intermediate: Multi-Process Producer-Consumer Pipeline with `multiprocessing.Queue`
Coordinating data extraction and transformation workers with poison pill shutdown sentinels.

```python
import multiprocessing
import time
import os

def ingestion_producer(queue: multiprocessing.Queue, count: int):
    for i in range(1, count + 1):
        item = f"DATA_RECORD_{i:04d}"
        queue.put(item)
        print(f"📥 [PRODUCED] {item} (PID: {os.getpid()})")
        time.sleep(0.05)

    # Send Poison Pill Sentinel to signal shutdown
    queue.put(None)

def compute_consumer(queue: multiprocessing.Queue):
    while True:
        item = queue.get()
        if item is None:  # Sentinel detected
            print(f"🛑 [CONSUMER EXIT] Shutdown signal received (PID: {os.getpid()})")
            break
        print(f"⚙️ [PROCESSED] Transforming {item} on PID: {os.getpid()}")
        time.sleep(0.1)

if __name__ == "__main__":
    ipc_queue = multiprocessing.Queue(maxsize=5)

    p1 = multiprocessing.Process(target=ingestion_producer, args=(ipc_queue, 4))
    c1 = multiprocessing.Process(target=compute_consumer, args=(ipc_queue,))

    p1.start(); c1.start()
    p1.join(); c1.join()
```

### 4. Real-World: High-Speed Zero-Copy Shared Memory Array
Sharing a memory buffer directly between parent and child processes using `multiprocessing.shared_memory`.

```python
import multiprocessing
from multiprocessing import shared_memory
import time
import os

def worker_shared_memory_updater(shm_name: str, size: int):
    # Attach to existing shared memory block allocated by parent!
    existing_shm = shared_memory.SharedMemory(name=shm_name)
    
    # Access raw byte buffer
    buf = existing_shm.buf
    print(f"⚙️ [CHILD PID {os.getpid()}] Reading initial byte at offset 0: {buf[0]}")
    
    # Mutate shared memory in-place with ZERO serialization!
    buf[0] = 99
    buf[1] = 42
    print(f"⚙️ [CHILD PID {os.getpid()}] In-place memory mutated directly.")
    
    existing_shm.close()

if __name__ == "__main__":
    # 1. Allocate 1000-byte shared memory block in OS RAM
    shm = shared_memory.SharedMemory(create=True, size=1000)
    
    # Initialize first bytes
    shm.buf[0] = 10
    shm.buf[1] = 20
    print(f"Parent Initial Memory: [{shm.buf[0]}, {shm.buf[1]}]")

    # 2. Spawn Child Process passing only the shared memory name
    proc = multiprocessing.Process(target=worker_shared_memory_updater, args=(shm.name, shm.size))
    proc.start()
    proc.join()

    # 3. Parent sees child mutations immediately with ZERO copying!
    print(f"Parent After Child Update: [{shm.buf[0]}, {shm.buf[1]}] (Mutated at native speed!)")

    # 4. Cleanup shared memory block
    shm.close()
    shm.unlink()  # Deallocate shared memory from operating system!
```

### 5. Advanced: Bidirectional Point-to-Point IPC with `multiprocessing.Pipe`
Building a full-duplex communication channel between two independent processes.

```python
import multiprocessing
import os

def microservice_endpoint(pipe_conn):
    pid = os.getpid()
    print(f"🔌 [SERVICE ONLINE] Process PID: {pid}")

    while True:
        message = pipe_conn.recv()
        if message == "SHUTDOWN":
            pipe_conn.send({"status": "OFFLINE", "pid": pid})
            break

        print(f"  Service received query: '{message}'")
        # Echo response back through pipe
        response = {"query": message, "result": "PROCESSED_SUCCESS", "handled_by_pid": pid}
        pipe_conn.send(response)

if __name__ == "__main__":
    # Create Full-Duplex 2-Way Connection Pipe
    parent_conn, child_conn = multiprocessing.Pipe(duplex=True)

    service_proc = multiprocessing.Process(target=microservice_endpoint, args=(child_conn,))
    service_proc.start()

    # Send Query through Pipe
    parent_conn.send("FETCH_ACCOUNT_METRICS")
    reply = parent_conn.recv()
    print("Parent Received Response:", reply)

    # Shutdown Service
    parent_conn.send("SHUTDOWN")
    shutdown_ack = parent_conn.recv()
    print("Service Acknowledged Shutdown:", shutdown_ack)

    service_proc.join()
```

## Code Explanation

In Example 4 (`SharedMemory`):
1. **`shared_memory.SharedMemory(create=True, size=1000)`** makes a system call (`shm_open` on POSIX) to allocate a shared memory segment in physical RAM.
2. The parent process passes only the **lightweight string identifier (`shm.name`)** to the child process.
3. The child calls `SharedMemory(name=shm_name)` to map the exact same physical RAM address into its own virtual address space.
4. When the child mutates `buf[0] = 99`, the parent sees the change **in under 10 nanoseconds**, bypassing the entire Pickling/Unpickling serialization pipeline.
5. Calling **`shm.close()`** detaches the process, and **`shm.unlink()`** releases the memory back to the OS kernel.

## Common Mistakes

### Mistake 1: Passing Unpicklable Objects to `Pool.map`
Attempting to pass lambda functions, local nested inner functions, or open file/socket handles to worker processes triggers `_pickle.PicklingError: Can't pickle local object`. All functions and arguments passed to `multiprocessing` must be **top-level, importable module objects**.

### Mistake 2: Forgetting to Call `shm.unlink()`
If you create a `SharedMemory` block and exit the program without calling `shm.unlink()`, the shared memory segment remains allocated in operating system RAM indefinitely until the computer is rebooted.

---

## Best Practices

### Tune `chunksize` in `Pool.map()`
When processing millions of small items, default `chunksize=1` causes massive IPC overhead because the pool sends items one by one. Set `chunksize` to:
$$\text{chunksize} = \frac{\text{Total Items}}{\text{CPU Cores} \times 4}$$
This batches items into efficient chunks, speeding up pool execution by **up to 10x**.

## Performance Considerations

| IPC Mechanism | Speed / Latency | Data Size Limit | Architecture |
|---|---|---|---|
| **`SharedMemory`** | **Instantaneous (< 10 ns)** | Limited only by RAM | **Zero-Copy Direct RAM Buffer** |
| **`Pipe`** | Fast (~15 $\mu$s) | Small / Medium Payloads| 2-Process Point-to-Point |
| **`Queue`** | Moderate (~40 $\mu$s) | Small Payloads | Multi-Producer / Multi-Consumer |
| **`Manager`** | Slow (~250 $\mu$s) | Any Python Object | Proxy IPC Server Process |

## Security Considerations

1. **Shared Memory Permissions**: On multi-user Linux/Unix servers, ensure `SharedMemory` names are cryptographically random to prevent other local OS users from reading sensitive data buffers from shared RAM.

## Advanced Concepts: The `forkserver` Start Method

To prevent threading deadlocks while maintaining high-speed process startup on Linux:

```python
import multiprocessing
# multiprocessing.set_start_method("forkserver")
```

The `forkserver` method starts a single-threaded daemon process on application startup. Whenever new worker processes are needed, the daemon forks clean, single-threaded child processes, avoiding inherited lock corruption.

## Mini Project: Enterprise Parallel ETL Matrix Compute Engine with Zero-Copy Shared Memory

### Requirements
Build an operational parallel matrix calculation pipeline named `parallel_matrix_engine.py`. Allocate a shared memory buffer, distribute non-overlapping data slices across worker processes, execute in-place calculations with zero serialization overhead, and render a performance benchmark report.

### Implementation Blueprint
```python
import multiprocessing
from multiprocessing import shared_memory
import struct
import time
import os

# =====================================================================
# 1. SHARED MEMORY WORKER FUNCTION (TOP-LEVEL FOR PICKLING)
# =====================================================================

def matrix_slice_worker(shm_name: str, start_idx: int, end_idx: int, multiplier: int):
    """Processes a slice of 32-bit integers directly inside shared physical RAM."""
    pid = os.getpid()
    
    # Attach to shared memory
    shm = shared_memory.SharedMemory(name=shm_name)
    
    # Each integer is 4 bytes (int32)
    for i in range(start_idx, end_idx):
        offset = i * 4
        # Read 32-bit int from raw memory
        val = struct.unpack_from("<i", shm.buf, offset)[0]
        # Write modified 32-bit int back in-place
        struct.pack_into("<i", shm.buf, offset, val * multiplier)

    shm.close()
    print(f"⚙️ [WORKER PID {pid}] Processed indices [{start_idx:,d} to {end_idx:,d}]")

# =====================================================================
# 2. PARALLEL MATRIX ENGINE ORCHESTRATOR
# =====================================================================

class ParallelMatrixEngine:
    INT_SIZE = 4  # 4 bytes for int32

    @classmethod
    def run_parallel_multiplication(cls, total_integers: int = 1_000_000, num_workers: int = 4):
        total_bytes = total_integers * cls.INT_SIZE
        
        border = "=" * 68
        print(border)
        print(f"      ENTERPRISE ZERO-COPY SHARED MEMORY MATRIX ENGINE")
        print(border)
        print(f"  • Total Matrix Integers : {total_integers:,d} items")
        print(f"  • Shared Buffer Size    : {total_bytes / (1024*1024):.2f} MB in RAM")
        print(f"  • Parallel CPU Workers  : {num_workers} processes")
        print("-" * 68)

        # 1. Allocate Shared Memory Segment in OS RAM
        shm = shared_memory.SharedMemory(create=True, size=total_bytes)

        try:
            # 2. Initialize array with integers: [1, 2, 3, ... N]
            print("Populating initial shared memory buffer...")
            for i in range(total_integers):
                struct.pack_into("<i", shm.buf, i * cls.INT_SIZE, i + 1)

            print(f"Initial First 4 Values : {[struct.unpack_from('<i', shm.buf, i * 4)[0] for i in range(4)]}")

            # 3. Calculate slice boundaries for each worker
            chunk_size = total_integers // num_workers
            processes = []

            start_time = time.perf_counter()

            # 4. Launch Worker Processes (Passing only shm.name!)
            for w in range(num_workers):
                start_i = w * chunk_size
                end_i = total_integers if w == num_workers - 1 else (w + 1) * chunk_size
                
                p = multiprocessing.Process(
                    target=matrix_slice_worker,
                    args=(shm.name, start_i, end_i, 10)  # Multiply by 10
                )
                processes.append(p)
                p.start()

            for p in processes:
                p.join()

            elapsed_sec = time.perf_counter() - start_time

            # 5. Verify Results in Parent Process (Zero-Copy Verification)
            print("-" * 68)
            updated_vals = [struct.unpack_from("<i", shm.buf, i * 4)[0] for i in range(4)]
            print(f"Updated First 4 Values : {updated_vals} (Multiplied by 10!)")
            print(f"Total Compute Duration : {elapsed_sec:.4f} seconds")
            print(f"Throughput Speed       : {total_integers / elapsed_sec:,.0f} integers/sec")
            print(border)

        finally:
            # 6. Unlink and deallocate shared memory
            shm.close()
            shm.unlink()
            print("🧹 Shared memory cleanly unlinked and released to OS.")

if __name__ == "__main__":
    ParallelMatrixEngine.run_parallel_multiplication(total_integers=500_000, num_workers=4)
```

## Summary

In this lesson, you mastered Multiprocessing, Pools, and IPC in Python:
- **`multiprocessing.Pool`** parallelizes batch operations across all CPU cores using **`map`**, **`apply_async`**, and **`imap`**.
- Configure **`maxtasksperchild`** in long-running pools to eliminate memory bloat and leak buildup.
- Use **`multiprocessing.Queue`** for multi-producer/multi-consumer workflows and **`Pipe`** for high-speed point-to-point IPC.
- **`multiprocessing.shared_memory.SharedMemory`** provides **Zero-Copy direct RAM sharing**, bypassing Pickling serialization overhead.
- Always call **`shm.close()`** and **`shm.unlink()`** to prevent memory leaks in the operating system kernel.
